# SEAM 스캐너 설계 (v1.1)

상태: **설계.** 구현은 S0 (대조 · 후보 도구 `seam/tests/engine/replay.mjs`) 까지.

## 1. 왜 만드는가

- TradingView 웹훅 알림은 유료 요금제(Essential 이상)에서만, 그것도 2단계 인증을 켠 계정에서만 됩니다. 무료 요금제에서는 지금 구조(지표 `alert()` → 릴레이 → 텔레그램)가 첫 단계에서 끊깁니다.
- 스펙 3절의 v1.1 후보가 바로 이것입니다: "워치리스트 스캐너 (자체 OHLC 로 동일 규칙 재실행)".
- 목표: TradingView 요금제와 상관없이 **같은 규칙으로 같은 알림**을 보냅니다. TradingView 는 눈으로 확인하는 화면으로 남습니다.

## 2. 구성

```
[거래소 공개 시세]   Binance 현물 봉 (키 없음)
       │  닫힌 봉만
       ▼
[seam-scanner]      워치리스트의 종목 × TF 마다 SEAM_Patterns.pine 을 오프라인 엔진으로 실행
       │  알림 JSON v1 (지표가 만드는 것과 같은 페이로드)
       ▼
[릴레이 코어]        스키마 검증 · 중복/과다 차단 · 토픽 라우팅 · 문구  (seam/relay/src/*.ts 를 그대로 import)
       │  Telegram Bot API
       ▼
[Telegram]          DM 또는 슈퍼그룹 토픽
```

스캐너가 텔레그램으로 직접 보냅니다. 받는 쪽 서버가 없으므로 공인 IP · 도메인 · HTTPS 인증서가 필요 없고, 나가는 연결만 씁니다.

## 3. 결정과 이유

### 3.1 규칙 원본은 하나: 같은 `.pine` 파일을 실행

- **선택**: 오프라인 Pine v6 엔진(piner)으로 `seam/pine/SEAM_Patterns.pine` 을 그대로 실행합니다.
- **이유**:
  - TypeScript 로 다시 짜면 규칙이 두 벌이 되어 언젠가 어긋납니다. 이 방식이면 지표를 고칠 때 스캐너도 같이 바뀝니다.
  - 회귀 시험(`seam/tests/engine`)이 이미 같은 엔진으로 돌고 있습니다.
- **성능**: 5000봉 한 번 실행에 약 0.3초가 걸렸습니다 (클라우드 개발 환경에서 측정).
- **전제**: 같은 봉을 넣었을 때 TradingView 와 같은 잠금값 · 같은 이벤트가 나와야 합니다. S1 대조(4절)로 확인합니다.
  - 차이가 엔진 쪽 문제로 밝혀지면, 그 부분만 Pine 에서 피해 가도록 고칩니다.
  - 그래도 안 맞으면 마지막 수단으로 TypeScript 포팅과 대조 시험을 함께 둡니다.
- **라이선스**: piner 는 AGPL-3.0, SEAM 은 MIT 입니다.
  - 지금 piner 는 시험용 개발 의존성입니다. 스캐너 실행에 쓰면 실행 의존성이 됩니다.
  - 본인 PC 에서 본인이 쓰는 것은 문제가 없습니다.
  - 스캐너를 배포하거나 다른 사람에게 서비스로 제공하면 스캐너에 AGPL 의무(소스 공개 등)가 붙습니다.
  - 그래서 스캐너는 별도 패키지(`seam/scanner/`)로 떼어 두고, 외부 제공 전에 다시 정합니다.

### 3.2 시세: Binance 현물부터

- **대조가 쉽습니다**: TradingView 의 `BINANCE:*` 차트는 Binance 봉을 그대로 씁니다.
- **호스트**: 공개 시세라 키가 필요 없습니다.
  - `data-api.binance.vision`(시세 전용)을 먼저 쓰고, 안 되면 `api.binance.com` 을 씁니다.
  - `api.binance.com` 은 미국 등 일부 지역에서 451 로 막힙니다.
- **요청량**: 봉마감마다 종목당 한 번, 최근 몇 봉만 받으므로 요청 한도에 여유가 큽니다.
- **다음 후보**: Upbit (KRW 마켓).
- **국내 · 미국 주식은 v1.1 범위 밖입니다.** 무료 공식 시세가 마땅치 않고, 수정주가와 시간외 처리 때문에 TradingView 와 봉이 달라집니다.

### 3.3 실행 위치: 본인 PC 상시 실행

| 후보 | 판단 |
|---|---|
| 본인 PC (Node 22.18+) | **1차.** 무료이고 봉마감 직후 바로 돕니다. 대신 PC 가 켜져 있어야 합니다 |
| GitHub Actions 예약 실행 | 제외. 예약이 수 분에서 수십 분 밀리고, GitHub 약관이 서버리스 용도와 저장소 개발에 무관한 작업을 금지합니다. 미국 러너라 Binance 본 API 도 막힙니다 |
| Cloudflare Workers 무료 | 제외. 예약 실행 CPU 한도가 10ms 라 Pine 엔진을 돌릴 수 없습니다. 유료 요금제는 한도가 커서 나중에 검토할 수 있습니다 |
| 무료 VM (Oracle Always Free 등) | 나중에. VPS 를 관리하는 부담은 같습니다 |

### 3.4 봉마감 판정 (PRINCIPLE 1)

- 닫힘 시각이 지난 봉만 엔진에 넣습니다. 진행 중인 봉은 넣지 않으므로 미리보기 알림이 없습니다.
- 타이머는 TF 경계 + 3초에 돕니다. 새 봉이 아직 안 보이면 잠시 뒤 다시 받습니다.

### 3.5 실행 방식 · 상태 · 재시작

- **매 봉마감마다 창 전체를 처음부터 다시 실행합니다.**
  - 창은 시작점이 고정되어 있고, 새 봉이 뒤에 붙으며 길어집니다.
  - 새로 닫힌 봉에서 생긴 이벤트만 보냅니다.
  - 봉 하나씩 이어 가는 방식보다 단순하고, 엔진 상태가 어긋날 일이 없습니다.
  - 이 방식은 "봉을 덜 넣고 돌린 결과가 전체 결과의 앞부분과 같다"(replay prefix)는 성질에 기댑니다. 이 성질은 이미 시험으로 확인하고 있습니다.
- **시작할 때**: 종목 · TF 마다 최근 N봉(기본 3000)을 받아 워밍업합니다. 이 구간의 이벤트는 보내지 않습니다 (과거 알림 폭주 방지).
- **창이 너무 커지면** (예: 20000봉) 시작점을 앞으로 당겨 다시 워밍업합니다.
  - 같은 구조는 같은 id(`ticker|tf|key|lock_ts`)를 가지므로 중복 차단에 걸려 다시 나가지 않습니다.
  - 다만 "시작점을 옮겨도 같은 봉에서 같은 값으로 잠긴다"는 성질은 아직 자동 시험이 없습니다. S2 에서 시험을 먼저 만듭니다.
- **상태 파일** `scanner-state.json` 에 두 가지를 적습니다.
  - (종목, TF) 별로 마지막으로 처리한 봉
  - 최근 보낸 이벤트 키 (`idempotencyKey`)
  - 재시작해도 이미 보낸 것은 다시 보내지 않습니다.
- **부하**: 1분봉 종목이 많으면 매분 전체 재실행이 무거워집니다 (1분봉 40개면 매분 10~20초). 그때는 봉 하나씩 이어 가는 방식으로 바꿉니다. 알림용으로는 5분봉 이상을 권장합니다.

### 3.6 알림 형식 · 설정 · 시크릿

- **알림 형식**: 페이로드는 지표와 같은 v1 JSON 입니다. 릴레이 코드로 검증하므로 문구와 토픽도 같고, 기본 이벤트도 같습니다 (lock · break_up · break_down · fail).
- **설정**: `seam/scanner/watchlist.json` 에는 종목 · TF 목록과 지표 입력(민감도, 표시 개수, 가족 토글)만 둡니다. 수치 입력은 두지 않습니다 (PRINCIPLE 7).
- **시크릿**: 봇 토큰과 채팅 ID 는 스캐너 env(`.env`, 커밋 안 함)에만 둡니다. S2 에서 CLAUDE.md 7번을 "릴레이 · 스캐너 env" 로 넓힙니다.
- **알림 경로는 하나만**: 나중에 TradingView 유료 요금제로 바꿔 두 경로를 같이 켜면, 릴레이와 스캐너의 중복 차단이 서로 공유되지 않아 같은 알림이 두 번 옵니다. 한 경로만 켭니다.

## 4. 검증 계획

1. **S1 대조**
   - `seam/tests/real/btcusdt-1m-2026-09-28.tv.json` 을 대조합니다. 2026-09-28 TradingView 확정 로그 8줄을 옮긴 파일입니다.
   - 같은 구간의 Binance 봉으로 `replay.mjs --expect` 를 돌립니다.
   - 일치하면 봉 파일을 커밋합니다. 이후 `npm test` 가 인터넷 없이 같은 대조를 돌립니다.
2. **대조 자료 늘리기**: 다른 TF(1시간 등)와 다른 종목으로 2~3건을 더 만듭니다. 사례 수집(`cases.md` 3절)과 같이 합니다.
3. **시작점 이동 시험**: 워밍업 시작을 바꿔도 lock_ts 와 잠금값이 같은지 자동 시험으로 확인합니다.
4. **스캐너 루프 시험**
   - 녹화한 봉을 가짜 시계로 한 봉씩 흘립니다.
   - 확인할 것: 각 이벤트가 정확히 한 번, 봉마감 뒤에만 나가는지. 재시작해도 다시 안 나가는지.
   - 전송은 dry-run 으로 대신합니다.

## 5. 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| S0 | 대조 · 후보 도구 `seam/tests/engine/replay.mjs`, 대조 자료 형식 | 완료 |

| S2 | `seam/scanner/`: 봉마감 타이머 · 창 재실행 · 상태 파일 · 릴레이 코어로 텔레그램 전송 · 시험 | S1 뒤 |
| S3 | PC 상시 실행 안내 (Windows · macOS), 텔레그램 봇 만들기 | S2 뒤 |
| S4 | Upbit 시세 | 필요할 때 |

## 6. 정해야 할 것

- 스캐너를 돌릴 PC: 상시 켜 두는 PC 가 있는지, OS 는 무엇인지.
- 첫 워치리스트: 종목과 TF. 1분봉은 잠금 직후 돌파가 잦아서, 알림용으로는 5분봉 이상을 권장합니다.
- 텔레그램: 개인 DM 인지, 슈퍼그룹 토픽인지.
